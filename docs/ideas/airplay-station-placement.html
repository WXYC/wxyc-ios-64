    Building it, given what we measured

    Status-only needs no UIKit at all — AVAudioSession.currentRoute.outputs.first?.portName plus the routeChangeNotification stream the player header already runs (PlayerHeaderView.swift:100). That is the version to build first; it is pure SwiftUI and cannot regress anything.

    Tappable stretches a real picker across the row and draws the row content underneath. Measured: the internal UIButton fills the bounds and a clear tint renders zero pixels, so the touch is genuine — no sendActions traversal, no silent-failure mode. Note StationView.swift already imports UIKit (line 26), so the exception CLAUDE.md asks about is already open in this file. 

    // The row's visuals are plain SwiftUI; the picker is an invisible tap layer on top.
// Order matters — the picker must be ABOVE to receive the touch.
ZStack {
    StationRowContent(                       // extracted from StationRow's body,
        title: "Play on a speaker",            // minus the Button wrapper
        subtitle: routeName ?? "This iPhone",
        systemImage: "airplayaudio",
        iconColor: .cyan
    )
    RoutePickerButton(tint: .clear, activeTint: .clear)
        .allowsHitTesting(true)
}
.accessibilityElement(children: .ignore)      // StationRow's contract (lines 300-302);
.accessibilityLabel("Play on a speaker")     // the picker's own "AirPlay" label would
.accessibilityValue(routeName ?? "This iPhone") // otherwise surface as a second element
.accessibilityAddTraits(.isButton)

    The one thing to verify on device: the accessibility merge above is written from the probe's finding that the inner button carries accessibilityLabel = "AirPlay" while isAccessibilityElement is false on both it and the container. That combination is unusual enough that it deserves a VoiceOver pass rather than trust in the snippet.
