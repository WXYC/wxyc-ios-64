Live Activities — five concepts, four presentations, two states each

Nothing here exists yet: NSSupportsLiveActivities is absent from the Info.plist and ActivityKit appears nowhere in the tree. But the app already declares the audio background mode, so while someone is listening the process is alive and the live-fs SSE stream can drive an activity locally — no APNs, no push budget. That splits these five concepts cleanly into local and push-gated.

Each concept is drawn in two states, because a Live Activity earns its place only if it changes while you are not looking at it. Flip the state and watch what moves.

The filter — added 2026-08-07 after reading the HIG

“Present only the most essential content. People appreciate getting a summary and key bits of information about an ongoing task or event; they don’t expect to receive a lot of details or to perform actions in a Live Activity.” Apple, Human Interface Guidelines — Live Activities. Apple has pre-refused the idea of using this surface as a metadata channel. Not a rejection risk; a design-intent statement.

So the question is not what else could we show. A fact earns a place on the card only if it is (a) absent from the system Now Playing card, (b) time-sensitive — it expires or changes on its own — and (c) actionable. All three, not two.

Passes
  • The DJ on the board — changes hourly, human, nowhere in the NP card
  • The tour join — expires, has a deadline, has a button
  • The Like button — an action, not a fact
Fails
  • Label, year, catalog number — true, static, already in the app
  • Critic review, rotation flag — interesting, not time-sensitive
  • Track title as the headline — the NP card owns it (see below)
The structural finding
  • Apple’s own docs call the Lock Screen media card a Live Activity. A now-playing card here would be a second Live Activity, same app, same audio, same stack. Concept 1 was re-cut because of this.

How to read these. The Lock Screen mock still draws the system Now Playing card underneath concept 1, because that is the honest objection — and the research made it sharper than expected. Apple's own user documentation calls that media card a Live Activity, so a now-playing card from this app would be a second Live Activity, same app, same audio, same stack. The re-cut concept 1 leads with the DJ and the time left in their show, which is a question nothing else on the device answers.

What the research changed. Three things. (1) App Review is not the obstacle — 2.5.16, 2.5.18 and 4.5.4 do not bite editorial metadata; only the ticket CTA and anything push-started need care. (2) The HIG is, and it pre-refuses a dense card: “they don't expect to receive a lot of details.” Hence the filter above. (3) Scope beats density — the way to earn the surface is to give the card a real event to be about (a show, a countdown, a timer) and let the metadata ride along as context.

What the numbers mean. The island's 126 × 37.33pt idle pill and the 160pt Lock Screen cap are real system constraints, drawn 1px = 1pt. Duration is confirmed by Apple DTS (Aug 2025): 8 hours active + 4 hours Lock Screen residue = 12 total, Dynamic Island cleared at 8. Everything else — paddings, type ramp, the 371pt expanded width — is a designer's guess. Do not port them into Swift without checking on device.

Reach, confirmed. iOS 26 renders Live Activities on the CarPlay home screen via supplementalActivityFamilies, reusing the Lock Screen view, plus the Mac menu bar and the Watch Smart Stack. visionOS is the only holdout. An earlier draft of this file hedged on CarPlay; it should not have.
