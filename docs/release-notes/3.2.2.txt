WXYC iOS — Release Notes
Version 3.2.2
Range: v3.2.1 (2026-08-10) → v3.2.2 (2026-08-28)

Distilled from the 303 commits since 3.2.1, filtered to what a listener actually experiences. Internal refactors, test infrastructure, CI, and documentation are excluded from the listener sections and summarized at the end.

3.2 and 3.2.1 built the live playlist, the richer track details, and the real-time on-air banner on WXYC's own flowsheet service, but every build shipped with the legacy endpoint compiled in as its default — so those features only reached the listeners a server-side flag happened to reach, and the flag could not safely be turned on for everyone. 3.2.2 makes the new API the app's own default, which is what finally delivers 3.2's headline feature to everyone who installs it.

Everything else is repair, and one repair is serious enough to stand next to the headline: the app has never once saved anything to the Keychain. Every 3.2 build asked for a storage area it holds no entitlement for, so the anonymous session the app signs in with was discarded at the end of every launch and rebuilt from nothing at the start of the next one. On top of that, sign-in could wedge outright, and a listener who hit that had an app that would not load anything for the rest of the launch. Alongside them: audio that could restart itself after you stopped it, a Now Playing screen that never let the phone go idle, a home-screen Play button that did nothing at all, and a widget handed blank playlists.


========================================================================
WHAT'S NEW IN 3.2.2 (scannable)
========================================================================

The live playlist, for everyone — The app now reads WXYC's flowsheet service directly instead of the legacy playlist endpoint. That is the only version with a push channel, so this is what turns on the real-time playlist, on-air banner, and mic-break markers 3.2 introduced — previously reachable only by remote configuration. Track details (release year, genres, artwork, streaming links) now arrive with the row rather than being fetched card by card, and the widget reads the same source as the app, so the two no longer disagree.

An app that can remember who it is — Every Keychain read and every Keychain write the app has made since 3.2 failed, without exception: 7,062 failures across 505 listeners in thirty days, on every iOS version from 15.7.3 to 27.0, with no other outcome ever recorded. The app was naming its storage area with the wrong identifier — the development team's, where this app's own identifier predates that convention — and asking for a Keychain group you are not entitled to fails every time. Nothing was ever saved and nothing was ever read back, so the app signed in as a brand-new anonymous listener on every single launch. The identifier is no longer written down anywhere; it now comes from the same place the entitlement itself does, which is the one copy that cannot disagree.

A home-screen Play button that plays — The Play/Pause button on the medium and large widgets never ran. The kind of action it used takes a required value, widgets do not fill those in, and so the system never entered the action at all: the button shimmered indefinitely and started nothing. It and the Control Center toggle now go through one constructor that cannot leave the value out.

Controls that agree with the stream — Starting or pausing from Siri, from the widget, or from Control Center left those controls showing the opposite of what the stream was doing. The value they render had exactly one writer — the app's own window — and an intent-driven launch never opens one. Every playback path now publishes it.

A request line that doesn't blame the booth — "Couldn't reach the booth" used to cover every failure, including one where the request never left the phone. That case now says so instead of reporting a station problem that isn't happening. At large text sizes the sheet scrolls rather than clipping its buttons off the bottom.

Streaming tiles that admit they're still looking — Opening a track the station is still enriching drew all five streaming tiles in the treatment that means "this service has no link for this record" — two opposite meanings wearing one appearance. A record still being looked up now reads as pending, and stops waiting after forty-five seconds rather than spinning for the life of the card.

WXYC 1983, in daylight — The theme chooses its light or dark gradient from the system appearance, but the app was pinning its entire window to dark to keep the status bar legible, so the theme's light half never appeared and its crossfade between the two never ran. The status bar never needed the pin — it was already set correctly elsewhere.

An app that can't wedge its own sign-in — The app signs in anonymously on first launch and quietly keeps that session alive; it is what lets the playlist, track details, and streaming links load at all. Two faults could break that session outright, leaving the app unable to load anything for the rest of the launch — and on a device whose Keychain is refusing writes, it recurred on every launch. Two more quietly created a brand-new anonymous account instead of reusing the one already held: one on every rejected token, one on every share-sheet presentation. All four are closed.

Stop means stop — Four ways a stopped or paused stream could start itself back up are fixed, including the one most likely to be noticed: pausing from the Lock Screen during a phone call, then having audio return on its own the moment the call ended.

A Now Playing screen that lets the phone settle — The pulsing green "live" dot was the only thing animating on an idle screen, and it was re-rendering the entire view tree on every display refresh to move a 9-point circle. Handing the pulse to the animation server drops idle CPU from 2.9% to 0.5% and stops the render loop entirely between updates. The dot also no longer jumps back to full brightness every time you pull down Control Center.

A widget that no longer goes blank — A background refresh that failed used to write its empty result into the cache the widget reads, stamped with a fresh fifteen-minute lifespan, so one failed refresh could leave the widget showing nothing for a quarter hour. An empty playlist is now never cached.

A widget that keeps up while you're listening — iOS lets a widget refresh for free while the app holds an active audio session, and the app was declining every one of those, so the listener whose widget most needed to track the flowsheet was the one watching it sit still. It now follows along change for change while the stream is playing.

Faster, steadier track details — Opening the playlist no longer fires duplicate lookups for the same album or artist, so detail cards fill in sooner on a cold launch. A momentary server hiccup is retried instead of being cached as "no such album," a rate limit is now respected rather than retried blind, and details repaired after a track finishes enriching are merged into the cache rather than lost. The Label row falls back to the station's own catalog when Discogs has nothing.

A more legible On Tour — Every status chip — on sale, sold out, rescheduled, free — now meets the AA contrast standard against its own fill; nine of the eighteen ink-and-fill pairs previously did not, the worst being the Box Office ticket's on-sale button at 1.67:1. The concert detail no longer stacks two identical status chips a few points apart.

Streaming links that go where they say — A Spotify link whose address isn't actually Spotify's no longer renders a green Spotify button that opens somewhere else.


========================================================================
EVERYTHING IN 3.2.2
========================================================================

IMPROVED
- The playlist reads api.wxyc.org/flowsheet by default instead of the legacy wxyc.info endpoint. This is the version gate for the rollout: it is compiled into the build rather than configured remotely, because older builds decode the new payload into an empty playlist and no server-side signal can reliably tell them apart. The feature flag keeps its rollback role — it can still pull a build back to the legacy endpoint without shipping a release.
- Real-time playlist updates, the live on-air banner, and mic-break markers are on by default as a consequence: the legacy endpoint has no push channel, so a five-minute poll was the ceiling on it.
- The live dot's pulse is now interpolated by Core Animation's render server instead of being stepped by the app every display refresh. Measured on an idle Now Playing screen: the view-graph display link goes from 150 samples in ten seconds to zero, display-list updates from 57 to zero, and process CPU from 2.9% to 0.5%. The dot is still pulsing; the app around it has stopped redrawing.
- Album and artist lookups for the same record are now shared rather than duplicated. Rendering a screenful of playlist rows on launch used to let each row issue its own identical request; concurrent callers now wait on the one already in flight.
- A failed metadata lookup is now classified before it is trusted. A server error, a rate limit, or a dropped connection is retried twice, briefly, so a condition that clears on the next poll is never recorded as a permanent answer; only a genuine 404 is treated as "this record has no details."
- When the server advertises how long to wait before retrying, the app honors that number if it fits inside what the fetch is willing to spend, and abandons immediately if it doesn't. A detail card asked to wait sixty seconds now fails fast instead of sitting there looking like a hang.
- Track details repaired after enrichment lands are written back into the cache, merged over what was already there so a field can only be added, never dropped — and a record still missing its artist link is held for fifteen minutes rather than a week, so a bio-less card repairs itself instead of persisting.
- The Label row now prefers the Discogs release label, falls back to the station's catalog record label, and only then to the label carried on the playlist row itself — so a record Discogs doesn't know still shows a label.
- In the Themes menu, j and k now switch the applied theme outright and wrap at both ends, so a keyboard user can flip through the set without opening the picker. With the picker open they behave like the arrow keys, browsing without committing; the arrows now wrap where they used to stop at the ends.
- Review cards in the track detail lost their tinted background panel and now sit directly on the surface behind them.
- Apple Intelligence can now recognize a WXYC DJ as a person and the station as a place, groundwork for richer Siri, Maps, and share behavior on iOS 26.4 and later.
- The home-screen widget now reloads on every flowsheet change while playback is active. iOS exempts a widget reload from its daily budget whenever the app is in the foreground or holding an audio session; the app honored only the first half, so a listener with the app alive in the background — receiving live playlist updates the whole time — had a widget that ignored all of them. Those reloads were always free.

FIXED
- Anonymous sign-in could wedge permanently. The client that talks to the auth service kept cookies in memory for the life of the process despite being configured not to persist them, so the second sign-in resent the first one's cookie and the server correctly refused it — "anonymous users cannot sign in again anonymously" — with every subsequent attempt resending the same cookie. Cookies are now refused at the session configuration and again on each individual request.
- A failed Keychain write no longer costs the session. The system occasionally refuses a write; the app used to read the resulting empty Keychain as "there is no session at all" and escalate to a full new sign-in, which was the one request guaranteed to fail. It now mints a fresh token from the session it is still holding in memory, which is exactly as valid.
- A token the server rejects no longer throws away the session underneath it. Forced re-authentication used to clear both, so every rejection created a brand-new anonymous account rather than renewing the existing one.
- The share extension rebuilt its authentication from scratch on every share-sheet presentation, creating another anonymous account each time on any device whose Keychain was refusing writes. It now sets itself up once per launch.
- A stall report that arrived just after you stopped could arm a reconnect, wake the audio session, and start playing again — on a listener who had deliberately paused. Reports that arrive after a stop are now discarded rather than acted on.
- The same was true of a connection error already in flight when you stopped: it overwrote the stopped state and reconnected. It is now held to the same rule the disconnect path already followed.
- Pausing from the Lock Screen during a phone call, then hanging up, brought audio back on its own. The pause is now recorded against the interruption, so ending the call resumes nothing you had already stopped.
- Stopping an already-stopped player ran the entire teardown anyway, allocating a fresh decoder and a new consumer task each time and filing a second "playback stopped" event. Seven of these landed in four seconds in one report. Stopping something already stopped is now free.
- A Siri pause closed out the listen without going through the path that records how long it lasted, so Siri-ended sessions were logged with no duration.
- A failed background refresh could write an empty playlist into the cache the widget reads, with a full fifteen-minute lifespan, replacing a miss that would have sent the widget to the network with a hit that serves it nothing. An empty playlist is never written to the cache now.
- The first thing to subscribe to the playlist on iOS is the widget's state service, and it received the cached playlist twice on every launch — spending a widget reload out of a limited daily budget on a duplicate, and making the now-playing service re-fetch artwork it already had.
- Switching between the two playlist APIs could leave the previous version's rows in flight; they would arrive after the switch and publish over it, putting two incompatible row orderings on screen at once.
- On Tour status chips are legible. Nine of eighteen ink-and-fill pairs were below the AA contrast threshold; the tinted near-whites that had been hue-matched to their own fills are now plain white, and the three chips with solid light fills keep their dark ink. A contrast floor in the test suite prevents a regression.
- The concert detail rendered a status chip in its hero and another, saying the same thing, in the Box Office ticket just below it. Only the ticket's remains — it sits with the price, door time, and the button it qualifies.
- A streaming link is now checked against the service it claims before it becomes a button. Deezer, Apple Music, Bandcamp, Qobuz, and Tidal addresses have all been observed in the Spotify field; a mismatched or malformed link falls back to the empty state instead of a mislabeled one.
- The live dot restarted its pulse from full brightness on any incidental update — a DJ signing on, the banner scrolling back into view, or pulling down Control Center and dismissing it. It now continues uninterrupted through all of those, and still restarts correctly after the system strips animations on backgrounding.
- Every Keychain read and write failed, on every device, in every 3.2 build. The app named its storage group with the development team's identifier; this app's own identifier is older than the convention that makes those the same, so the group it asked for was one it holds no entitlement for. Neither the sign-in session nor the device identifier behind the request line has ever survived a launch. The value is now expanded by the build system into the app's own information file, from the same variable that produces the entitlement, so there is no second copy left to be wrong. Confirmed on device: the first successful write under the correct identifier, surviving both a relaunch and a delete-and-reinstall.
- The Play/Pause button on the home-screen widget never did anything. Its action declared a required value that widgets, unlike Siri, do not resolve, so the system never ran the action — and since the widget only redraws once an action returns, the button's placeholder shimmer never cleared either. Both that button and the Control Center toggle are now constructed through one initializer that supplies the value.
- A start or pause issued from Siri, the widget, or Control Center left those controls displaying the opposite of what playback was doing. The state they read was written only from the app's own window, which an intent-driven launch never opens; all four paths now write it, before the system redraws the widget.
- A request that failed before it ever left the phone reported that the booth was unreachable. That was wrong in the one direction a listener might act on, and it was indistinguishable in telemetry from the booth actually being down. The two are separated now.
- A failure that reached the booth no longer speculates about what the booth thought of it. One case used to read "the booth turned that one down — try rewording your request," describing a judgment nothing in the system can make: a DJ has no way to decline a request, and the only non-transient rejection the service returns is for an empty message the app refuses to send in the first place. It is gone rather than reworded.
- The request sheet clipped its buttons at larger text sizes. It was budgeting a fixed height for the tallest combination of failure text, Dynamic Type, and a three-line request field; it now scrolls.
- The WXYC 1983 theme only ever rendered its dark gradient. A status-bar workaround was pinning the whole window's appearance, which overrode the theme's own light/dark branch — and disabled the crossfade that runs when the appearance changes, since that fires on a window change that could no longer happen. The workaround is gone; the status bar is set from the app's information file, as it already was.
- A track the station was still enriching showed all five streaming tiles in the "no link on this service" treatment. The card was asking whether anything had answered yet, but the first answer arrives promptly and carries no links, so the question was settled before the repair that fills the tiles had landed. Pending is now its own state, visibly and for VoiceOver, and it gives up after forty-five seconds rather than never.


========================================================================
UNDER THE HOOD (not listener-visible)
========================================================================

Roughly nine in ten commits in this range are internal. They are recorded here because the raw commit count otherwise misrepresents the release.

- A codebase-wide refactor and test-infrastructure audit: consolidated test doubles into shared CoreTesting and CachingTesting helpers, replaced wall-clock sleeps in the playback and logger suites with deterministic gates, unified duplicated URL-session mocks, and extracted shared transport and decode paths across the v1/v2 playlist, artwork, and MusicShareKit packages.
- Presentation seams for the forthcoming native macOS target, plus macOS availability on the six audio-schema intent types so the Intents package builds for the host.
- A Debug-only launch crash: the playlist service's environment default ran an assertion from its static initializer, which SwiftUI evaluates while processing a correct injection, not only on a miss. It fired on every Debug launch and took every simulator test run with it. The same shadow instance was also doing real work on every launch — a defaults read, a fetcher construction, and a disk cache read for a service nothing subscribes to; cache loading is now deferred to first use, with a barrier so the background-refresh path can't read a baseline that hasn't loaded.
- Crash and performance reporting was rebuilt around being able to tell traffic apart: the environment is now set explicitly so developer and simulator runs stop reading as production, app hangs are grouped by their innermost in-app frame instead of fragmenting across sampled stacks, Mac Catalyst builds are classified from the right provisioning-profile path, and app-launch profiling is armed for TestFlight builds only with explicit stop conditions so a single measurement build can't profile forever.
- The dSYM upload is now a gate rather than a suggestion: CI archives and local archives both fail if symbols don't upload, with a documented developer override, a pinned sentry-cli on Xcode Cloud runners, and a Homebrew fallback for the archive environment's reduced PATH.
- A server-advertised Retry-After is now carried on HTTP status errors as a Duration, range-checked at the type boundary so a hostile header can't be turned into an unbounded sleep.
- The Donate row is built and wired to the station config, and ships dark: it renders only when the backend explicitly enables it, which requires a Backend-Service deploy that hasn't happened yet.
- The generated contract type is now the app's AppConfig, re-exported from AppServices rather than duplicated, and the contract pin advanced to wxyc-shared 1.36.0. The /config endpoint is fetched at launch, ahead of the authenticated secrets retry loop so it isn't skipped on a cold launch with no auth.
- The v1 playlist decode is now pinned against Backend-Service's wire golden and 4,911 production URL values. One malformed URL on one row fails the whole array decode and blanks the playlist on that path, so the server-side guard is the only defense; the test records exactly which values would take the feed down.
- The on-air field the banner reads is pinned by JSON shape across all three of its states. An explicit null decodes silently to "unknown" and hides the banner rather than throwing, which is the quiet failure the pin exists to catch.
- Test coverage for a class of blank detail card — rows marked enriched server-side with every value withheld — fixed upstream in Backend-Service and now guarded from the client side.
- CI script hardening: structural-versus-cosmetic project-file classification for affected-test selection, crash detection in the SPM parity check, derived-data paths kept out of the working tree, contract-type verification on pull requests and master pushes, and a shared harness behind the shell test suites.
- The debug HUD attached a display link and two timers at construction and never released them, sampling at display rate for a HUD that ships hidden; sampling now starts and stops with visibility.
- The Handoff activity type is derived from the running bundle identifier instead of being hardcoded in two places, so Debug and Release builds no longer advertise the same activity and can't continue each other's.
- A rate-change observer in the HLS player was registering unscoped because a cast through a wrapper always failed. No effect today with one player alive; corrected before a second one makes it real.
- The Wallpaper submodule gains two Plasma controls — a compressor on the wave's excursion and a makeup brightness offset — both exact no-ops at their defaults, so the shipped look is unchanged.
- Time actually spent in front of the listener is now measured. The existing background events record only the edges, and the analytics vendor's own session length spans background playback because the playback heartbeat keeps a session alive with the phone in a pocket — so nothing measured on-screen time. A foreground_session event now reports it per visit, counting a Control Center pull as part of the visit rather than the end of one.
- Like and unlike events, and the detail-view and streaming-link events beside them, now carry the song, artist, and album they refer to. The tally they feed was re-scoped to aggregate counts only, so what is recorded is which records are being liked, not who liked them.
- The widget's decaying refresh schedule and its freshness label were both built during this range and withdrawn before release. The schedule bought a cold widget a nearly-free day at the cost of one belonging to a listener who hadn't opened the app; the label was the only reader of a second, future-dated timeline entry. Both are gone, along with the timeline event's refresh-interval and staleness properties, which existed to validate them. The budget-exempt reload path they sat beside is untouched — that is the half a listener actually feels. Historical analytics keeps what it already recorded.
- Analytics now starts before the sharing and request stack is configured, rather than nine lines after it. Events captured during that configuration were being dropped outright, which is why a device identifier that was failing on every launch for a month reported nothing at all — and why an empty measurement was twice mistaken for a working one.
- The device identifier reports which of its four storage outcomes it reached, on every launch, on success and failure alike, so a reading of zero can no longer be mistaken for a fix.
- Feature-flag evaluation is now recorded even when the flag provider is missing, which turned out to be the case for the entire shipped fleet: the request line's authentication has never been enabled for any listener, in any released build. Two independent omissions, neither of them a decision anyone recorded.
- Every answered status now renders identically to an unanswered one, so no failure copy varies with what the booth returned. This is what keeps a shadow ban unprobeable: the ban arrives as a 403 with no token on the unauthenticated path, so any case that told statuses apart on screen was one status away from being a ban indicator. The status code is still reported to PostHog under its own key, taken from the error rather than from the classification, so collapsing the cases cost no measurement.
- Further presentation seams for the native macOS target: launch setup extracted, artwork and clock views made cross-platform, external links routed through the environment's opener, and the On Tour share and calendar surfaces guarded.
- Build and test scripts resolve a simulator at run time instead of naming one. A hardcoded device is local to one machine and one Xcode version, and a stale one fails minutes into a build in a way that reads as a broken script.
- CI now reports when the pinned wxyc-shared API contract goes stale against that repository's main branch, and files a tracking issue if the drift check itself cannot run — a check that fails silently is indistinguishable from one that passes.
